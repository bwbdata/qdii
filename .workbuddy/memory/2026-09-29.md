## 摸清项目运行方式（用户问「怎么运行起来」）

结论：本项目不是常驻服务，没有 `npm start`。由三块组成：

1. **CLI 查询**：`node scripts/query-purchase-limits.js`，实测 3 秒出结果（代销数据 57/57 完整）。
   - 结果默认写 `~/.qdii-purchase-limits/`；加 `--output-dir .qdii-purchase-limits` 可写到项目内（该目录已被 .gitignore 忽略）。
   - 首次只建基线，第二次起才会报额度/状态变化。
2. **H5 页面**：`web/public/`，数据在同目录 `data/latest.json`，用 fetch 读取 → 必须经 HTTP 服务预览，直接双击 index.html 会被 CORS 拦掉。
   - 刷新数据：`node scripts/query-purchase-limits.js --output-dir .qdii-purchase-limits` → `npm run build:web-data -- --input .qdii-purchase-limits/latest.json`
3. **定时/云端**：macOS 用 `scripts/manage-macos-automation.js`（09:10/14:30/20:30，默认关闭），云端走 GitHub Actions + Cloudflare Worker。

## 坑

- **`node scripts/build-web-data.js --help` 不是安全操作**：该脚本不解析 `--help`，会直接执行默认构建。
  默认 input `.qdii-purchase-limits/latest.json`、默认 output `web/public/data/latest.json`，
  即会直接覆盖仓库里被 git 跟踪的 CI 数据产物。本次误触发后文件从 52508 字节降到 28611 字节，
  已用 `git restore web/public/data/latest.json` 恢复，工作区最终保持干净。
  查参数请直接读脚本源码（`scripts/build-web-data.js` 只有 `--input` / `--output` 两个参数）。
- 本地预览需在命令里加 `--noproxy '*'` 才能 curl 通本机端口（环境里 HTTP_PROXY 会拦 127.0.0.1）。
