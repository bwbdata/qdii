## 摸清项目运行方式（用户问「怎么运行起来」）

结论：本项目不是常驻服务，没有 `npm start`。由三块组成：

1. **CLI 查询**：`node scripts/query-purchase-limits.js`，实测 3 秒出结果（代销数据 57/57 完整）。
   - 结果默认写 `~/.qdii-purchase-limits/`；加 `--output-dir .qdii-purchase-limits` 可写到项目内（该目录已被 .gitignore 忽略）。
   - 首次只建基线，第二次起才会报额度/状态变化。
2. **H5 页面**：`web/public/`，数据在同目录 `data/latest.json`，用 fetch 读取 → 必须经 HTTP 服务预览，直接双击 index.html 会被 CORS 拦掉。
   - 刷新数据：`node scripts/query-purchase-limits.js --output-dir .qdii-purchase-limits` → `npm run build:web-data -- --input .qdii-purchase-limits/latest.json`
3. **定时/云端**：macOS 用 `scripts/manage-macos-automation.js`（09:10/14:30/20:30，默认关闭），云端走 GitHub Actions + Cloudflare Worker。

## 坑

- **`node scripts/build-web-data.js --help` 不是安全操作**：该脚本不解析 `--help`，会直接执行默认构建。
  默认 input `.qdii-purchase-limits/latest.json`、默认 output `web/public/data/latest.json`，
  即会直接覆盖仓库里被 git 跟踪的 CI 数据产物。本次误触发后文件从 52508 字节降到 28611 字节，
  已用 `git restore web/public/data/latest.json` 恢复，工作区最终保持干净。
  查参数请直接读脚本源码（`scripts/build-web-data.js` 只有 `--input` / `--output` 两个参数）。
- 本地预览需在命令里加 `--noproxy '*'` 才能 curl 通本机端口（环境里 HTTP_PROXY 会拦 127.0.0.1）。

## 返工：按钮改单个 + 浏览器缓存坑（2026-09-29 傍晚）

用户反馈四条：按钮没和状态行同一行、要整合成一个按钮、表头不见了、点费率不切换。

**根因：不是代码问题，是浏览器缓存。** 落盘与服务端返回的文件都是新版，但用户页面里跑的是**旧的 app.js + styles.css**（新的 index.html 已加载，所以按钮能看到）。症状组合起来正好指向它：新 HTML 的表头是空容器 + 旧脚本不渲染表头 → 表头空白；旧脚本没有切换逻辑 → 点击无效；旧 CSS 没有 `.status-bar` → 按钮掉到下一行。

**修法：给引用加内容哈希。** `index.html` 里改成 `styles.css?v=<sha256前8>` 与 `app.js?v=<sha256前8>`，资源一变 URL 就变，缓存自然失效。新增 `tests/web-assets.test.js` 断言令牌与文件哈希一致（已实测：篡改令牌会被测出）。**以后改了 app.js / styles.css，必须同步更新 index.html 的令牌**，否则测试直接 FAIL。

按钮形态：两段式 `.view-switch/.view-tab` 已废弃，改成单个 `<button id="view-toggle">`，内部两个 `.view-label[data-view]`，靠 `active` 类区分当前视图（额度绿字加粗 / 费率灰字）。`applyViewToggle()` 在 `render()` 里统一同步标签与 `aria-label`，点击处理器只翻转 `view` 再 `render()`。布局靠 `.view-toggle { margin-left: auto }` 顶到状态行右侧。

**冒烟脚本的坑**：假 DOM 桩必须把 `textContent`（写入时转义）与 `innerHTML`（读取）打通到同一字段，否则 `safe()` 恒返回空串，会出现「表头 ok、数据行全空」的**假失败**。改桩后 15/15 通过，且真能验证点一次、再点一次的完整往返。

## 费率视图排序 + A 类基准（2026-09-29 傍晚，第二轮回访）

需求：切到费率时也要排序，同名份额以 A 类为排序基准。

做法（全在 `web/public/app.js`）：
- **分组键**：`shareBase()` 去掉 `人民币` 与 `(人民币)` 写法差异；`shareClassLetter()` 只认**结尾紧跟非拉丁字符的单个大写字母**（正则 `/[^A-Za-z]([A-Z])$/`），这样 `天弘标普500发起(QDII-FOF)` 结尾的 F 不会被误当份额类别。`groupKey()` 再去掉该字母。
- **组基准**：`basisByBase` 取组内 `classRank` 最小**且有费率**的份额。A 类有费率时就是 A 类；A 缺失或未公示时退回 C 等。组内固定按 `classRank`（A=0,C=1,E=2,I=3,F=4,D=5，其余=50）再按代码。
- 费率视图按基准**降序**（费率高的在前，用户第三轮明确要求），未公示费率的（`sortFee` 非有限值）排最后；额度视图逻辑不变，仍按额度降序。
- 两处顺带修掉的坑：① 组内顺序原来比**原始名称**，而「人民币」有时插在类别字母前（如 `…(QDII)人民币I` vs `…(QDII)A`），会把同组拆散 → 改用归一化 `base` 比较；② `finalAmount()` 在字段缺失时返回 `undefined`，比较器算出 `NaN` 导致排序随机 → 统一归一成数字或 `null`。

**真实数据实测**（`data/latest.json` 57 行）：识别出 23 个同名分组，全部满足「组基准 = A 类费率」「A 类排组内第一」「同名连续」；费率视图基准序列 1.2→0.6 **单调不增**；额度视图顺序未变（100/100/10…）。

已知未合并的一组：`021778 广发纳指100ETF联接(QDII)人民币F` 与 `270042/006479 广发纳斯达克100ETF联接…` 名称里「纳指100」和「纳斯达克100」写法不同，按字符串分组没有并到一起，目前它单独成组。是否同一只基金待用户确认，**不能凭猜测合并**。

新增 `tests/web-view-sort.test.js`：把 app.js 整份塞进 `vm` + 最小假 DOM，用合成数据断言两个视图的完整代码顺序。注意首屏默认只渲染 `nasdaq100`，要断言全量顺序得先点「全部」那个 tab。
